# Phase572 independent directional-transition adjudicator

Phase572 is the independent adjudication surface for the registered-target
directional replay and reset-at-checkpoint transition probe. It has no project
reference to, source include from, or shared implementation with Phases570,
571, or 545.

The implementation independently reconstructs the periodic mesh incidence,
the exact and winding closed-form subspaces, their union and orthogonal
complement projectors, registered-target configuration, xoshiro256** and
Box-Muller draws, leapfrog proposals, committed-chain replay, and the frozen
diagnostic estimators. Objective and gradient values use the exact-bound
production evaluator; their formula is not claimed as independently
reimplemented. Planted controls execute before audited Phase570 or Phase571
numerical data are parsed.

The original non-executable pending scaffold is preserved under
lineage/pending/. The frozen-but-unexecuted v1 and the detected post-freeze
source-drift attempt are preserved under lineage/ with honest stop records.
Neither supports a scientific terminal.

The successor v4 contract was frozen before Phase572's first execution after
Phase570 v7 and Phase571 v4 completed. It exact-binds both upstream
contracts, sole launch programs, projects, full outputs and summaries; the
Phase571 v3 resource-refusal attempt and current lineage; the final Phase572
program/project; and the direct immutable target inputs.

Phase572 reconstructs the actual Phase570 catalog of 18 invariant series
rather than coordinate directions. It also reconstructs the exact Phase571
Cartesian menu of six checkpoints, two disclosed seeds, two antithetic signs,
and four frozen arms. Duplicate, missing, extra, or row-mutated proposals fail
closed. The 1.25 improvement threshold, 0.8 degradation floor, three-of-four
panel rule, and five-of-six endpoint rule are independently applied.

The unexecuted v2 and v3 freezes are also preserved: their final audits found
contract semantics that the executable had not asserted. The first v4
execution reached output serialization, then stopped with exit code 134
because the deliberately divergent planted control's nonfinite `deltaH` was
reported as a raw JSON number. No transcript was captured and neither output
file was created; the exact v4 bytes and an honest non-citable attempt record
are preserved under `lineage/v4-frozen/`.

The compile-clean v5 successor changed no scientific threshold. It reports
the expected nonconvex `deltaH` as nullable with an explicit finite flag,
requires that control to be nonfinite, divergent, and rejected, and adds a
recursive pre-write safety gate. Any unexpected nonfinite diagnostic is
converted to JSON null, recorded by path, and routed to the earliest
applicable failure or disagreement terminal. Named floating-point JSON
literals remain forbidden. Its pre-execution audit nevertheless found that a
later nonfinite category could overwrite an already-earlier terminal, and
that preconverted production proposal `deltaH` values could escape detection.
V5 is therefore preserved as an unexecuted stop under `lineage/v5-frozen/`.

The v6 successor added common precedence and emitted/printed identity, but a
post-freeze self-audit found that lag-one and drift-Z production diagnostics
were still preconverted. Its exact bytes are preserved as an unexecuted stop
under `lineage/v6-frozen/`.

The v7 successor keeps all production diagnostic values raw through its recursive
scan, allowlists only the planted nonconvex decoy for preconversion, and
combines nonfinite routing with the already-selected terminal by the frozen
earliest precedence. Unknown paths route to invalid input. Planted controls
cover replay-before-transition, directional-before-transition, favorable to
transition failure, and unknown-before-replay collisions, and require the
emitted and printed terminals to agree. A dedicated planted production fixture
requires raw lag-one NaN and drift-Z infinities to be detected, null-converted,
and routed to the directional-disagreement terminal. V7 has not been executed, so no
Phase572 output or scientific terminal exists yet.

Even a confirming terminal can authorize only later planning. It cannot
reinterpret the Phase548/549 terminals, consume a protected blind seed,
advance a new Markov chain, select a production default, discharge external
review, or support a physical-unit claim.
